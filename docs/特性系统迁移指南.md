# 特性系统迁移指南

## 概述

我们已经引入了**特性系统（Feature System）**，采用**混合模式**（继承 + 组合）来扩展技能类型。

### 设计理念

- **核心类型用继承**：`ActiveAbility`、`PassiveAbility`（这些是真正的技能类型）
- **行为特性用组合**：`ComboFeature`、`ProjectileFeature`、`ChannelingFeature`、`MagicFieldFeature`（这些是可组合的行为）
- **通用支持**：特性系统同时支持主动技能和被动技能，但钩子方法不同

### 优势

1. **灵活组合**：可以任意组合特性，如"连击+投射物"、"引导+魔法场"等
2. **避免组合爆炸**：不需要为每种组合创建新类
3. **向后兼容**：现有技能类仍然可用（已标记为 deprecated）
4. **数据驱动**：可以在编辑器中配置特性组合

## 已实现的特性

### ✅ ComboFeature（连击特性）

**位置**：`addons/godot_gameplay_abilities/scripts/abilities/features/combo_feature.gd`

**功能**：
- 管理多段连击
- 连击重置计时器
- 推进连击索引

**使用示例**：
```gdscript
var ability = ActiveAbility.new()
var combo_feature = ComboFeature.new()
combo_feature.combo_abilities = [attack_1, attack_2, attack_3]
combo_feature.combo_reset_time = 1.0
ability.features.append(combo_feature)
```

### ✅ ProjectileFeature（投射物特性）

**位置**：`addons/godot_gameplay_abilities/scripts/abilities/features/projectile_feature.gd`

**功能**：
- 生成投射物
- 支持多重施法（散射）
- 投射物追踪

**使用示例**：
```gdscript
var ability = ActiveAbility.new()
var projectile_feature = ProjectileFeature.new()
projectile_feature.projectile_data = my_projectile_data
projectile_feature.projectile_count = 3
projectile_feature.spread_angle = 30.0
ability.features.append(projectile_feature)
```

### ✅ ChannelingFeature（引导特性）

**位置**：`addons/godot_gameplay_abilities/scripts/abilities/features/channeling_feature.gd`

**功能**：
- 支持两种模式：按住施法（HOLD_TO_CHANNEL）和切换式（TOGGLE）
- 管理引导生命周期（启动、停止、Tick 循环）
- 周期性消耗检查（tick_costs）
- 中断检查（interrupt_tags）
- 引导标签管理（self_channeling_tags）

**使用示例**：
```gdscript
var ability = ActiveAbility.new()
var channeling_feature = ChannelingFeature.new()
channeling_feature.channeling_mode = ChannelingFeature.ChannelingMode.HOLD_TO_CHANNEL
channeling_feature.max_duration = 5.0
channeling_feature.tick_interval = 0.5
channeling_feature.tick_costs = [mana_cost]
ability.features.append(channeling_feature)
```

### ✅ MagicFieldFeature（魔法场特性）

**位置**：`addons/godot_gameplay_abilities/scripts/abilities/features/magic_field_feature.gd`

**功能**：
- 生成魔法场
- 魔法场位置计算（支持多种位置来源）
- 魔法场数据应用

**使用示例**：
```gdscript
var ability = ActiveAbility.new()
var magic_field_feature = MagicFieldFeature.new()
magic_field_feature.magic_field_data = my_magic_field_data
ability.features.append(magic_field_feature)
```

## 迁移步骤

### 从 ComboAbility 迁移到 ComboFeature

**旧方式**：
```gdscript
var ability = ComboAbility.new()
ability._combo_abilities = [attack_1, attack_2, attack_3]
ability._combo_reset_time = 1.0
```

**新方式**：
```gdscript
var ability = ActiveAbility.new()
var combo_feature = ComboFeature.new()
combo_feature.combo_abilities = [attack_1, attack_2, attack_3]
combo_feature.combo_reset_time = 1.0
ability.features.append(combo_feature)
```

**示例1：连击+投射物技能**：
```gdscript

# 添加连击特性

```

## 向后兼容

### 已标记为 Deprecated 的类

以下类仍然可用，但建议迁移到特性系统：

- `ComboAbility` → 使用 `ComboFeature + ActiveAbility`
- `ProjectileAbility` → 使用 `ProjectileFeature + ActiveAbility`
- `ChannelingAbility` → 使用 `ChannelingFeature + ActiveAbility`
- `MagicFieldAbility` → 使用 `MagicFieldFeature + ActiveAbility`

### 迁移时间表

- **第一阶段（当前）**：特性系统已可用，现有类标记为 deprecated
- **第二阶段（6-12个月）**：完成所有特性的迁移，提供迁移工具
- **第三阶段（1-2年）**：完全移除 deprecated 类（如果用户已全部迁移）

## 特性系统 API

### AbilityFeature 基类

所有特性都继承自 `AbilityFeature`，提供以下钩子方法：

#### 主动技能钩子（仅对 ActiveAbility 有效）

```gdscript
# 检查是否可以施法
func can_cast(ability: GameplayAbility, context: AbilityContext) -> bool

# 提交施法时的处理
func commit_cast(ability: GameplayAbility, context: AbilityContext) -> bool

# 技能实际生效时的处理
func on_cast(ability: GameplayAbility, context: AbilityContext) -> void

# 技能被取消时的处理
func on_cancel(ability: GameplayAbility, context: AbilityContext) -> void

# 技能完成时的处理
func on_completed(ability: GameplayAbility) -> void
```

#### 被动技能钩子（仅对 PassiveAbility 有效）

```gdscript
# 技能学习时的处理
func on_learned(ability: GameplayAbility, ability_comp: Node, status_comp: Node) -> void

# 技能遗忘时的处理
func on_forgotten(ability: GameplayAbility, ability_comp: Node, status_comp: Node) -> void
```

#### 通用钩子（对所有技能类型有效）

```gdscript
# 每帧更新（用于需要持续更新的特性）
func update(ability: GameplayAbility, delta: float) -> void
```

### ActiveAbility 中的特性支持

`ActiveAbility` 现在支持 `features` 数组：

```gdscript
@export var features: Array[AbilityFeature] = []
```

特性执行顺序：
1. `can_cast`：所有特性的 `can_cast` 都必须返回 `true`
2. `commit_cast`：所有特性的 `commit_cast` 都必须返回 `true`
3. `on_cast`：按顺序执行所有特性的 `on_cast`
4. `update`：每帧调用所有特性的 `update`
5. `on_cancel`：技能被取消时调用所有特性的 `on_cancel`
6. `on_completed`：技能完成时调用所有特性的 `on_completed`

### PassiveAbility 中的特性支持

`PassiveAbility` 现在也支持 `features` 数组：

```gdscript
@export var features: Array[AbilityFeature] = []
```

特性执行顺序：
1. `on_learned`：技能学习时按顺序执行所有特性的 `on_learned`
2. `update`：每帧调用所有特性的 `update`（如果技能组件在更新）
3. `on_forgotten`：技能遗忘时按顺序执行所有特性的 `on_forgotten`

### 被动技能特性示例

被动技能可以使用特性来实现复杂行为，例如：


## 常见问题

### Q: 特性之间如何通信？

A: 通过 `AbilityContext` 的 `custom_data` 字典传递数据。例如，`ComboFeature` 会将连击索引写入 `context.custom_data["combo_index"]`。

### Q: 特性执行顺序重要吗？

A: 是的。`on_cast` 按数组顺序执行，如果特性之间有依赖关系，需要注意顺序。

### Q: 可以创建自定义特性吗？

A: 可以！继承 `AbilityFeature` 并实现所需的钩子方法即可。注意：
- 如果特性只用于主动技能，只需实现主动技能钩子（can_cast, commit_cast, on_cast 等）
- 如果特性只用于被动技能，只需实现被动技能钩子（on_learned, on_forgotten）
- 如果特性是通用的，可以实现 `update` 方法

### Q: 被动技能可以使用主动技能的特性吗？

A: 技术上可以，但通常没有意义。主动技能的特性（如 `ComboFeature`、`ProjectileFeature`）依赖于主动技能的施放流程，被动技能没有这些流程。建议为被动技能创建专门的特性（如条件触发、事件监听等）。

### Q: 现有技能资源需要重新创建吗？

A: 不需要。现有技能资源仍然可用，但建议逐步迁移到特性系统以获得更好的灵活性。

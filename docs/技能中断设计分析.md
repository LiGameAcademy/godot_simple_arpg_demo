# 技能中断设计分析

## 当前实现

### 当前逻辑（`GameplayAbilityComponent.commit_cast()`）

```gdscript
# 检查是否已有技能在执行
if not _current_casting_ability_id.is_empty() and _current_casting_ability_id != ability_id:
    if can_interrupt():
        # 后摇阶段：允许用新技能取消当前技能的后摇
        cancel_ability(_current_casting_ability_id, ctx)
    else:
        # 前摇阶段：不允许后摇取消，返回 false
        return false
```

**特点**：
- 允许同一技能继续执行（用于连击、切换技能）
- 不同技能：后摇阶段可以取消，前摇阶段不允许
- 强制中断：通过 `cancel_ability()` 方法，任何阶段都可以中断

---

## 用户提出的设计

### 设计要点

1. **重复释放同一技能**：无效（忽略）
2. **释放另一个技能**：打断当前技能（无论前摇还是后摇）
3. **强制打断**：如果允许，则打断当前技能

### 设计分析

#### 优点

1. **简单明确**：规则清晰，易于理解
2. **响应迅速**：玩家输入立即响应，不会卡顿
3. **符合直觉**：新输入总是优先于旧输入

#### 潜在问题

1. **重复释放无效**：
   - ❌ 连击技能需要重复释放同一技能
   - ❌ 切换技能（Toggle）需要重复释放来关闭
   - ❌ 引导技能可能需要重复释放来停止
   - ✅ 普通技能确实应该忽略重复释放

2. **无条件打断**：
   - ❌ 前摇阶段打断可能导致资源浪费（如果使用 COMMIT 模式，资源已消耗）
   - ❌ 某些技能可能需要在特定阶段保护（如无敌帧）
   - ✅ 后摇阶段打断是合理的（后摇取消）

3. **缺少阶段区分**：
   - ❌ 前摇和后摇应该有不同的处理逻辑
   - ❌ 某些技能可能需要在生效后不允许打断

---

## 推荐设计

### 方案 A：改进的当前设计（推荐）

#### 核心规则

1. **重复释放同一技能**：
   - 由技能自己决定（通过 `can_cast()` 和 `commit_cast()`）
   - 连击技能：允许重复释放（在连击窗口内）
   - 切换技能：允许重复释放（切换开关）
   - 引导技能：允许重复释放（停止引导）
   - 普通技能：默认不允许（`can_cast()` 返回 false）

2. **释放另一个技能**：
   - **前摇阶段**：根据配置决定
     - 如果使用 COMMIT 模式（资源已消耗）：不允许打断，返回 false
     - 如果使用 CAST 模式（资源未消耗）：允许打断，取消当前技能
     - 如果技能标记为"不可中断"：不允许打断
   - **后摇阶段**：允许打断（后摇取消）

3. **强制打断**：
   - 提供 `cancel_ability()` API
   - 任何阶段都可以强制中断
   - 但需要明确调用，不是自动的

#### 实现要点

```gdscript
func commit_cast(ability_id: StringName, target: Node = null, context: Variant = {}) -> bool:
    # 1. 检查是否已有技能在执行
    if not _current_casting_ability_id.is_empty():
        if _current_casting_ability_id == ability_id:
            # 同一技能：由技能自己决定（连击、切换等）
            # 技能会在 can_cast() 中处理
            pass
        else:
            # 不同技能：检查是否可以打断
            var current_ability = get_ability_data(_current_casting_ability_id)
            if is_instance_valid(current_ability):
                # 检查当前技能是否允许中断
                if current_ability.has_method("can_be_interrupted"):
                    if not current_ability.can_be_interrupted():
                        return false
                
                # 检查阶段
                if can_interrupt():
                    # 后摇阶段：允许打断
                    cancel_ability(_current_casting_ability_id, ctx)
                else:
                    # 前摇阶段：根据配置决定
                    if _should_allow_precast_interrupt(current_ability):
                        cancel_ability(_current_casting_ability_id, ctx)
                    else:
                        return false
    
    # 2. 继续执行新技能...
```

#### 核心规则

1. **重复释放同一技能**：无效（忽略）
2. **释放另一个技能**：无条件打断
3. **强制打断**：提供 API

#### 实现要点

func commit_cast(ability_id: StringName, target: Node = null, context: Variant = {}) -> bool:

#### 适用场景

- **快节奏游戏**：需要快速响应玩家输入
- **简单技能系统**：没有复杂的连击、切换机制
- **动作游戏**：强调操作流畅性

## 推荐方案：混合设计

### 核心原则

1. **灵活性优先**：由技能自己决定是否允许重复释放和中断
2. **阶段区分**：前摇和后摇有不同的处理逻辑
3. **配置驱动**：通过技能属性控制中断行为

### 实现建议

#### 1. 在 `GameplayAbility` 中添加中断控制

```gdscript
@export_group("Interruption Rules")
## 是否允许在前摇阶段被其他技能打断
@export var can_be_interrupted_in_precast: bool = false
## 是否允许在后摇阶段被其他技能打断（后摇取消）
@export var can_be_interrupted_in_postcast: bool = true
## 是否允许重复释放（用于连击、切换技能）
@export var allow_repeat_cast: bool = false
```

#### 2. 在 `commit_cast()` 中实现逻辑

```gdscript
func commit_cast(ability_id: StringName, target: Node = null, context: Variant = {}) -> bool:
    # 检查是否已有技能在执行
    if not _current_casting_ability_id.is_empty():
        if _current_casting_ability_id == ability_id:
            # 同一技能：检查是否允许重复释放
            var current_ability = get_ability_data(_current_casting_ability_id)
            if is_instance_valid(current_ability):
                # 由技能自己决定（通过 can_cast）
                # 连击技能会在 can_cast 中检查连击窗口
                # 切换技能会在 can_cast 中处理切换逻辑
                if not current_ability.can_cast(self, target, context):
                    return false
        else:
            # 不同技能：检查是否可以打断
            var current_ability = get_ability_data(_current_casting_ability_id)
            if is_instance_valid(current_ability):
                var can_interrupt_now = false
                
                if can_interrupt():
                    # 后摇阶段
                    can_interrupt_now = current_ability.can_be_interrupted_in_postcast
                else:
                    # 前摇阶段
                    can_interrupt_now = current_ability.can_be_interrupted_in_precast
                
                if can_interrupt_now:
                    cancel_ability(_current_casting_ability_id, ctx)
                else:
                    return false
    
    # 继续执行新技能...
```

## 结论

### 用户设计的评价

**优点**：
- 简单直接，易于实现
- 响应迅速，符合快节奏游戏需求

**缺点**：
- 不支持连击、切换等复杂机制
- 前摇阶段无条件打断可能导致资源浪费
- 缺少灵活性

### 推荐方案

**采用混合设计**：
1. **默认行为**：类似用户设计（简单直接）
2. **可配置**：通过技能属性控制中断行为
3. **向后兼容**：现有技能无需修改即可工作

这样既满足了简单场景的需求，又保留了复杂场景的灵活性。

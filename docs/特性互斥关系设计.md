# 特性互斥关系设计

## 特性互斥关系分析

### 1. 单例特性（同一类型只能有一个）

这些特性在同一个技能中只能存在一个实例：

- **`ComboFeature`**：连击逻辑冲突，多个连击特性会导致状态混乱
- **`ChannelingFeature`**：引导逻辑冲突，多个引导特性会导致状态混乱
- **`ActiveFeature`**：主动技能流程冲突，多个主动特性会导致流程混乱
- **`PassiveFeature`**：被动技能流程冲突，多个被动特性会导致状态管理混乱
- **`CooldownFeature`**（待实现）：冷却管理冲突，多个冷却特性会导致冷却时间混乱
- **`CostFeature`**（待实现）：消耗管理冲突，多个消耗特性会导致资源消耗混乱

### 2. 可能互斥的组合

这些特性组合可能产生逻辑冲突：

- **`ComboFeature` + `ChannelingFeature`**：
  - 连击需要快速切换，引导需要持续施法
  - 可能互斥，但也可以设计为兼容（如"引导连击"）

- **`ProjectileFeature` + `MagicFieldFeature`**：
  - 投射物是移动的，魔法场是固定的
  - 通常互斥，但也可以设计为兼容（如"投射物落地后生成魔法场"）

- **`ActiveFeature` + `PassiveFeature`**：
  - 主动和被动可以共存（混合技能）
  - **不互斥**，这是设计目标之一

### 3. 兼容的组合

这些特性可以安全组合：

- **`ActiveFeature` + `ProjectileFeature`**：主动投射物技能
- **`ActiveFeature` + `ComboFeature`**：主动连击技能
- **`ActiveFeature` + `ChannelingFeature`**：主动引导技能
- **`ActiveFeature` + `MagicFieldFeature`**：主动魔法场技能
- **`ActiveFeature` + `CooldownFeature` + `CostFeature`**：完整的主动技能

## 验证机制设计

### 方案 1：运行时验证（推荐）

在 `GameplayAbility` 中添加验证方法，在关键时机检查特性配置：

```gdscript
## 验证特性配置
## [return] Array[String] 错误信息列表，空数组表示无错误
func validate_features() -> Array[String]:
    var errors: Array[String] = []
    var feature_counts: Dictionary = {}
    
    # 统计每个特性类型的数量
    for feature in features:
        if not is_instance_valid(feature):
            continue
        var feature_type = feature.get_script().get_path().get_file().get_basename()
        if not feature_counts.has(feature_type):
            feature_counts[feature_type] = 0
        feature_counts[feature_type] += 1
    
    # 检查单例特性
    var singleton_features = [
        "ComboFeature",
        "ChannelingFeature",
        "ActiveFeature",
        "PassiveFeature",
        "CooldownFeature",
        "CostFeature"
    ]
    
    for feature_type in singleton_features:
        var count = feature_counts.get(feature_type, 0)
        if count > 1:
            errors.append("特性 '%s' 只能存在一个实例，但发现了 %d 个" % [feature_type, count])
    
    # 检查互斥组合
    var has_combo = feature_counts.get("ComboFeature", 0) > 0
    var has_channeling = feature_counts.get("ChannelingFeature", 0) > 0
    if has_combo and has_channeling:
        errors.append("警告：ComboFeature 和 ChannelingFeature 可能互斥，请确认设计意图")
    
    var has_projectile = feature_counts.get("ProjectileFeature", 0) > 0
    var has_magic_field = feature_counts.get("MagicFieldFeature", 0) > 0
    if has_projectile and has_magic_field:
        errors.append("警告：ProjectileFeature 和 MagicFieldFeature 可能互斥，请确认设计意图")
    
    return errors
```

### 方案 2：自动去重（容错）

如果检测到重复的单例特性，自动只保留第一个：

```gdscript
## 清理重复的特性（自动去重）
func _cleanup_duplicate_features() -> void:
    var seen_types: Dictionary = {}
    var cleaned_features: Array[AbilityFeature] = []
    
    for feature in features:
        if not is_instance_valid(feature):
            continue
        
        var feature_type = feature.get_script().get_path().get_file().get_basename()
        var singleton_features = [
            "ComboFeature",
            "ChannelingFeature",
            "ActiveFeature",
            "PassiveFeature",
            "CooldownFeature",
            "CostFeature"
        ]
        
        if feature_type in singleton_features:
            if seen_types.has(feature_type):
                push_warning("GameplayAbility: 检测到重复的特性 '%s'，已自动移除重复项" % feature_type)
                continue
            seen_types[feature_type] = true
        
        cleaned_features.append(feature)
    
    features = cleaned_features
```

### 方案 3：特性注册表（扩展性）

使用特性注册表定义互斥规则：

```gdscript
## 特性注册表（定义互斥规则）
var FEATURE_RULES = {
    "singleton": [
        "ComboFeature",
        "ChannelingFeature",
        "ActiveFeature",
        "PassiveFeature",
        "CooldownFeature",
        "CostFeature"
    ],
    "mutually_exclusive": [
        ["ComboFeature", "ChannelingFeature"],  # 可能互斥
        ["ProjectileFeature", "MagicFieldFeature"]  # 可能互斥
    ]
}
```

## 推荐实现

### 混合方案：验证 + 自动去重

1. **运行时验证**：在关键时机（如 `_ready()`、`can_cast()`）调用 `validate_features()`
2. **自动去重**：在初始化时自动清理重复的单例特性
3. **警告提示**：对于可能互斥的组合，发出警告但不阻止执行

### 实现位置

- **`GameplayAbility`**：添加验证和清理方法
- **`ActiveAbility`**：在初始化时调用验证（向后兼容）
- **编辑器脚本**（可选）：在编辑器中实时验证

## 使用示例

```gdscript
# 错误配置：多个连击特性
var ability = GameplayAbility.new()
ability.features = [
    ComboFeature.new(),
    ComboFeature.new()  # 重复！
]
var errors = ability.validate_features()
# errors = ["特性 'ComboFeature' 只能存在一个实例，但发现了 2 个"]

# 自动清理
ability._cleanup_duplicate_features()
# 现在只有一个 ComboFeature

# 警告配置：可能互斥的组合
var ability2 = GameplayAbility.new()
ability2.features = [
    ComboFeature.new(),
    ChannelingFeature.new()  # 可能互斥
]
var errors2 = ability2.validate_features()
# errors2 = ["警告：ComboFeature 和 ChannelingFeature 可能互斥，请确认设计意图"]
```

---

## 结论

**推荐方案**：
1. 实现运行时验证（`validate_features()`）
2. 实现自动去重（`_cleanup_duplicate_features()`）
3. 在关键时机调用验证（初始化、施放前）
4. 对于可能互斥的组合，发出警告但不阻止执行（给设计者灵活性）

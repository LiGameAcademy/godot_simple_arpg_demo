# 技能中断设计改进方案

## 用户提出的设计

### 核心规则

1. **重复释放同一技能**：无效（忽略）
2. **释放另一个技能**：打断当前技能（无论前摇还是后摇）
3. **强制打断**：如果允许，则打断当前技能

### 设计评价

#### ✅ 优点

1. **简单直接**：规则清晰，易于理解和实现
2. **响应迅速**：玩家输入立即响应，不会卡顿
3. **符合直觉**：新输入总是优先于旧输入

#### ❌ 潜在问题

1. **重复释放无效**：
   - ❌ **连击技能**：需要重复释放同一技能来触发下一段
   - ❌ **切换技能**：需要重复释放来切换开关状态
   - ❌ **引导技能**：可能需要重复释放来停止引导
   - ✅ **普通技能**：确实应该忽略重复释放

2. **无条件打断**：
   - ❌ **资源浪费**：前摇阶段打断可能导致资源浪费（COMMIT 模式下资源已消耗）
   - ❌ **缺少保护**：某些技能可能需要在特定阶段保护（如无敌帧）
   - ✅ **后摇打断**：后摇阶段打断是合理的（后摇取消）

3. **缺少阶段区分**：
   - ❌ 前摇和后摇应该有不同的处理逻辑
   - ❌ 某些技能可能需要在生效后不允许打断

## 推荐改进方案

### 方案：配置驱动的中断系统

#### 核心设计

在 `GameplayAbility` 中添加中断控制属性：

```gdscript
@export_group("Interruption Rules")
## 是否允许重复释放（用于连击、切换技能）
## true: 允许重复释放，由技能自己决定是否接受（通过 can_cast）
## false: 不允许重复释放，直接返回 false
@export var allow_repeat_cast: bool = false

## 是否允许在前摇阶段被其他技能打断
## true: 允许打断（会取消前摇，资源可能已消耗）
## false: 不允许打断（前摇锁死）
@export var can_be_interrupted_in_precast: bool = false

## 是否允许在后摇阶段被其他技能打断（后摇取消）
## true: 允许打断（后摇取消，提升操作流畅性）
## false: 不允许打断（必须等待后摇完成）
@export var can_be_interrupted_in_postcast: bool = true

## 是否允许强制中断（通过 cancel_ability API）
## true: 允许强制中断（任何阶段都可以）
## false: 不允许强制中断（只能等待自然完成）
@export var can_be_force_cancelled: bool = true
```

#### 实现逻辑

```gdscript
func commit_cast(ability_id: StringName, target: Node = null, context: Variant = {}) -> bool:
    var ctx = ContextUtils.to_context(context)
    var ability_data = get_ability_data(ability_id)
    
    # 检查是否已有技能在执行
    if not _current_casting_ability_id.is_empty():
        if _current_casting_ability_id == ability_id:
            # 同一技能：检查是否允许重复释放
            var current_ability = get_ability_data(_current_casting_ability_id)
            if is_instance_valid(current_ability):
                if not current_ability.allow_repeat_cast:
                    # 不允许重复释放，直接返回 false
                    return false
                # 允许重复释放，由技能自己决定（通过 can_cast）
                # 连击技能会在 can_cast 中检查连击窗口
                # 切换技能会在 can_cast 中处理切换逻辑
        else:
            # 不同技能：检查是否可以打断
            var current_ability = get_ability_data(_current_casting_ability_id)
            if is_instance_valid(current_ability):
                var can_interrupt_now = false
                
                if can_interrupt():
                    # 后摇阶段
                    can_interrupt_now = current_ability.can_be_interrupted_in_postcast
                else:
                    # 前摇阶段
                    can_interrupt_now = current_ability.can_be_interrupted_in_precast
                
                if can_interrupt_now:
                    cancel_ability(_current_casting_ability_id, ctx)
                else:
                    # 不允许打断，返回 false
                    return false
    
    # 继续执行新技能...
```

## 不同技能类型的默认配置

### 普通技能（默认）

```gdscript
allow_repeat_cast = false
can_be_interrupted_in_precast = false
can_be_interrupted_in_postcast = true
can_be_force_cancelled = true
```

### 连击技能

```gdscript
allow_repeat_cast = true  # 允许重复释放
can_be_interrupted_in_precast = false
can_be_interrupted_in_postcast = true
can_be_force_cancelled = true
```

### 切换技能

```gdscript
allow_repeat_cast = true  # 允许重复释放来切换
can_be_interrupted_in_precast = false
can_be_interrupted_in_postcast = true
can_be_force_cancelled = true
```

### 引导技能

```gdscript
allow_repeat_cast = true  # 允许重复释放来停止
can_be_interrupted_in_precast = true  # 前摇可以打断
can_be_interrupted_in_postcast = true
can_be_force_cancelled = true
```

### 蓄力技能（需要保护）

```gdscript
allow_repeat_cast = false
can_be_interrupted_in_precast = false  # 前摇锁死
can_be_interrupted_in_postcast = false  # 后摇也锁死
can_be_force_cancelled = false  # 不允许强制中断
```

## 实现建议

### 阶段 1：添加中断控制属性

在 `GameplayAbility` 基类中添加中断控制属性。

### 阶段 2：更新 `commit_cast()` 逻辑

根据中断控制属性决定是否允许打断。

### 阶段 3：更新特性系统

在 `ActiveFeature` 中添加中断控制属性，支持特性级别的配置。

### 阶段 4：更新现有技能

为现有技能设置合适的中断控制属性。

## 结论

### 用户设计的评价

**优点**：
- 简单直接，易于实现
- 响应迅速，符合快节奏游戏需求

**缺点**：
- 不支持连击、切换等复杂机制
- 前摇阶段无条件打断可能导致资源浪费
- 缺少灵活性

### 推荐方案

**采用配置驱动的中断系统**：
1. **默认行为**：类似用户设计（简单直接）
2. **可配置**：通过技能属性控制中断行为
3. **向后兼容**：现有技能无需修改即可工作（使用默认值）

这样既满足了简单场景的需求，又保留了复杂场景的灵活性。

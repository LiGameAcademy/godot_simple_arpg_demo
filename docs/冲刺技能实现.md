# 📘 技术设计文档：通用物理位移效果 (GE_PhysicsMotion)

**版本：** v1.0
**适配架构：** Godot Gameplay Ability System (GAS)
**适用场景：** 冲锋 (Charge)、闪避 (Dash)、击退 (Knockback)、跳斩位移

## 1. 设计目标 (Design Goals)

1.  **非侵入式 (Non-Intrusive)：** 不修改 `Player` 或 `MovementComponent` 的现有代码，不依赖 `velocity` 属性。
2.  **物理安全 (Physics Safe)：** 使用 `move_and_collide` 代替 `global_position` 修改，防止穿墙、掉出地图。
3.  **手感丝滑 (Game Feel)：** 支持 **“贴墙滑动 (Wall Sliding)”**，避免角色在狭窄地形卡死。
4.  **高度可配 (Data Driven)：** 通过 `Curve` 曲线控制速度变化（如爆发起步、缓慢停止）。

-----

## 2. 核心逻辑流程 (Core Logic)

我们将使用 Godot 的 `Tween` 系统来驱动一个“虚拟的时间轴”，但在每一帧的回调中执行物理检测。

### 算法步骤：

1.  **初始化：** 锁定冲锋方向，计算目标总距离。
2.  **时间步进 (Tween Step)：** `Tween` 将进度从 `0.0` 推向 `1.0`。
3.  **距离映射：** 根据 `Curve` 采样，计算当前时刻**应该**累积移动的距离。
4.  **增量计算：** `本帧位移量 = 目标累积距离 - 已累积距离`。
5.  **物理执行：**
      * 调用 `body.move_and_collide(本帧位移向量)`。
      * **IF** 发生碰撞 -\> 获取碰撞法线 -\> 计算滑动向量 (`remainder.slide(normal)`) -\> 再次移动剩余距离。
6.  **结束：** 触发回调，移除相关 Tags（如无敌、禁锢）。

-----

## 3. 参数定义 (Parameters)

| 参数名 | 类型 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| `distance` | float | 6.0 | 位移总距离（米） |
| `duration` | float | 0.3 | 位移总时间（秒） |
| `speed_curve` | Curve | EaseOut | **核心手感参数**。X轴为时间进度，Y轴为距离权重。建议使用“快进慢出”。 |
| `direction_type` | Enum | INPUT | 方向策略：`FORWARD`(面朝), `INPUT`(键盘), `MOUSE`(鼠标), `CUSTOM` |
| `ignore_gravity` | bool | false | 是否忽略重力。地面冲锋建议 `false` (贴合斜坡)，空中冲刺建议 `true`。 |
| `apply_tags` | Array[String] | ["state.dashing"] | 位移期间赋予的标签（如无敌、霸体）。 |

## 4. 伪代码实现 (Implementation)

这是基于 Godot 4.x 的 GDScript 实现，可以直接用于你的插件。

```gdscript
extends GameplayEffect
class_name GE_PhysicsMotion

# --- 配置区 ---
@export_group("Motion Config")
@export var distance: float = 6.0
@export var duration: float = 0.3
@export var speed_curve: Curve
@export var ignore_gravity: bool = false

enum DirectionType { FORWARD, INPUT, MOUSE, CUSTOM }
@export var direction_type: DirectionType = DirectionType.INPUT

# --- 核心应用逻辑 ---
func _apply(target: Node, instigator: Node, context: Dictionary) -> void:
    # 1. 守卫：必须是物理实体
    var body = target as CharacterBody3D
    if not body: 
        push_warning("GE_PhysicsMotion: Target is not CharacterBody3D")
        return

    # 2. 计算方向 (这是冲锋瞬间锁定的，过程不可变)
    var move_dir = _resolve_direction(body, context)
    
    # 3. 准备 Tween (必须在 Physics Process 运行以保证碰撞稳定)
    var tween = body.create_tween()
    tween.set_process_mode(Tween.TWEEN_PROCESS_PHYSICS)
    tween.set_trans(Tween.TRANS_LINEAR) # 线性时间，曲线逻辑我们在回调里自己算
    
    # 4. 状态闭包：用于在回调中记录上一帧走到哪了
    var state = { "accumulated_dist": 0.0 }
    
    # 5. 赋予 Tag (通过 AbilityComponent)
    var ability_comp = _find_ability_component(body)
    if ability_comp:
        ability_comp.add_tag("state.movement.forced") # 比如：冲锋中
        ability_comp.add_tag("state.invulnerable")    # 比如：无敌
    
    # 6. 启动驱动器：0.0 -> 1.0
    tween.tween_method(
        _physics_process_step.bind(state, body, move_dir),
        0.0, 1.0, duration
    )
    
    # 7. 清理回调
    tween.finished.connect(func():
        if ability_comp:
            ability_comp.remove_tag("state.movement.forced")
            ability_comp.remove_tag("state.invulnerable")
    )

# --- 物理步进回调 (每物理帧调用) ---
func _physics_process_step(progress: float, state: Dictionary, body: CharacterBody3D, dir: Vector3) -> void:
    # A. 采样曲线：获取当前进度对应的"距离百分比"
    # 如果没有配置曲线，则线性移动
    var dist_percent = speed_curve.sample(progress) if speed_curve else progress
    
    # B. 计算本帧目标位置 (Total Target)
    var target_accum_dist = distance * dist_percent
    
    # C. 计算本帧增量 (Delta Step) = 目标总量 - 已走总量
    var step_dist = target_accum_dist - state["accumulated_dist"]
    
    # 更新记录，供下一帧使用
    state["accumulated_dist"] = target_accum_dist
    
    # 如果这一帧位移极小，忽略 (避免浮点抖动)
    if step_dist <= 0.001: return
    
    # D. 构建位移向量
    var velocity_vector = dir * step_dist
    
    # E. 简易重力处理 (贴地逻辑)
    # 如果不忽略重力，且不在地面，给一个向下的分量确保贴合斜坡
    if not ignore_gravity and not body.is_on_floor():
        # 这里给一个固定的下压力，或者根据重力公式估算
        velocity_vector.y -= 0.5 
    
    # F. 【关键】物理执行与滑墙逻辑
    var collision = body.move_and_collide(velocity_vector)
    
    if collision:
        # 撞墙了！计算滑动向量
        var normal = collision.get_normal()
        var remainder = collision.get_remainder() # 撞击后剩余没走完的距离
        
        # 沿着墙面法线滑动
        var slide_vector = remainder.slide(normal)
        
        # 如果滑动分量有效，再次移动
        if slide_vector.length() > 0.001:
            body.move_and_collide(slide_vector)

# --- 辅助：方向解析 ---
func _resolve_direction(body: Node3D, context: Dictionary) -> Vector3:
    var dir = -body.global_transform.basis.z # 默认前方
    
    match direction_type:
        DirectionType.INPUT:
            # 获取输入向量 (假设 Input Map 已配置)
            var input = Input.get_vector("move_left", "move_right", "move_up", "move_down")
            if input.length() > 0.1:
                # 转换到相机空间
                var cam = body.get_viewport().get_camera_3d()
                var cam_basis = cam.global_transform.basis
                dir = (cam_basis.x * input.x + cam_basis.z * input.y).normalized()
        
        DirectionType.MOUSE:
            if context.has("mouse_world_pos"):
                dir = (context["mouse_world_pos"] - body.global_position).normalized()
    
    dir.y = 0 # 强制水平冲锋
    return dir.normalized()

func _find_ability_component(node: Node) -> Node:
    # 你的查找组件逻辑
    return node.get_node_or_null("GameplayAbilityComponent")
```

## 5. 为什么这个设计是最好的？

1.  **解决了"增量"难题：**
    传统的 `Tween` 是基于属性插值的。如果我们直接插值 `velocity`，很难控制精确的移动距离（受帧率影响积分误差）。
    本方案通过 `accumulated_dist` 记录\*\*"由于曲线变化，我现在应该在哪里"**，然后计算差值。这保证了无论帧率如何波动，0.3秒后通过的**总距离\*\*一定是精确的 `distance`。

2.  **完美的"滑墙"手感：**
    `move_and_collide` 返回的 `collision` 对象包含 `remainder`（剩余距离）。利用 `remainder.slide(normal)`，我们实现了物理引擎底层的滑动逻辑。
    *如果不做这一步，角色撞到墙就会瞬间卡停，手感像撞到了隐形胶水。*

3.  **零耦合：**
    这个脚本不引用你的 `Player.gd`，不修改 `velocity` 变量。你可以把它挂在怪物身上，甚至挂在飞行的火球上（只要它是 CharacterBody3D），效果完全一致。

### 一、 技能如何触发完成回调？是否需要？

**结论：非常需要。**

在 GAS 架构中，\*\*“完成（Finished）”\*\*意味着一个事务的闭环。对于位移技能，如果缺少完成回调，会导致以下严重后果：

1.  **Tag 无法移除：** 角色会一直处于“无敌”或“正在冲锋”状态，甚至可能导致无法再次移动（如果逻辑层锁死了输入）。
2.  **连招断档：** 无法通知连招系统“我冲完了，你可以接下一招了”。
3.  **表现层卡死：** 拖尾特效可能永远关不掉。

**如何实现：**
在上一节的 `GE_PhysicsMotion` 中，利用 `Tween` 的 `finished` 信号是最佳时机。

```gdscript
# GE_PhysicsMotion.gd (片段)

func _apply(target, ...):
    # ... Tween 创建逻辑 ...
    
    # 【回调处理】
    tween.finished.connect(func():
        # 1. 移除状态 Tag (核心逻辑闭环)
        if ability_comp:
            ability_comp.remove_tag("state.movement.forced")
            ability_comp.remove_tag("state.invulnerable")
        
        # 2. (可选) 如果需要通知 Ability 层面技能结束
        # 这一步视你的 Ability 实现而定，如果是 Instant 技能通常不需要
        # 但如果是 Channeling 技能，这里需要调用 ability.end_ability()
    )
```

### 二、 技能的表现效果如何处理？

在 GAS 架构中，我们要严格遵守 **“逻辑驱动表现”** 的原则。
不要在 `GE_PhysicsMotion`（逻辑脚本）里写生成特效的代码。

**最佳实践流程：**

1.  **逻辑层 (Effect):** 修改组件的 Tag（如添加 `state.movement.forced`）。
2.  **表现层 (VFX Manager):** 监听组件的 `tag_changed` 信号。
      * 检测到有 `state.movement.forced` -\> **开启** 拖尾生成器。
      * 检测到 Tag 移除 -\> **关闭** 拖尾生成器。

### 三、 Shader 实现拖尾残影 (Ghost Trail)

这是你想要的“开发日志高光时刻”！
实现拖尾通常不需要复杂的屏幕后处理 Shader，最适合 Godot 的方案是 **“网格快照 + 材质褪色”**。

#### 1\. 准备：幽灵材质 Shader (ghost.gdshader)

新建一个 Shader，让残影呈现一种半透明、单色、且随时间消散的效果。

```glsl
shader_type spatial;
render_mode unshaded, blend_mix, cull_disabled; // 无光照，混合模式，双面渲染

uniform vec4 color : source_color = vec4(0.0, 0.8, 1.0, 0.8); // 基础色（青色）
uniform float alpha_factor : hint_range(0.0, 1.0) = 1.0; // 控制消散的透明度

void fragment() {
    ALBEDO = color.rgb;
    ALPHA = color.a * alpha_factor;
}
```

#### 2\. 实现：残影生成器组件 (GhostTrailGenerator.gd)

把这个脚本挂在角色身上（Visuals 节点下）。

```gdscript
extends Node3D
class_name GhostTrailGenerator

@export_group("Settings")
@export var emit_interval: float = 0.05  # 生成间隔（秒）
@export var duration: float = 0.4        # 残影存活时间
@export var ghost_material: ShaderMaterial # 拖入上面写的 Shader 材质
@export var target_mesh: MeshInstance3D  # 要复制的网格（主角模型）

var _timer: float = 0.0
var _is_active: bool = false
var _ability_comp: Node = null

func _ready() -> void:
    # 自动查找 AbilityComponent 并连接信号
    # 假设组件挂在角色的根节点
    var owner_node = get_parent()
    if owner_node.has_method("get_component"): # 适配你的组件查找方式
        _ability_comp = owner_node.get_component("GameplayAbilityComponent")
    elif owner_node.get_node_or_null("GameplayAbilityComponent"):
        _ability_comp = owner_node.get_node("GameplayAbilityComponent")
        
    if _ability_comp:
        # 监听 Tag 变化 (假设你有 tag_changed 信号)
        # 信号签名通常是: tag_changed(tag: StringName, count: int)
        if _ability_comp.has_signal("tag_changed"):
            _ability_comp.tag_changed.connect(_on_tag_changed)
        # 或者监听具体的 ability_completed 信号也可以，但 Tag 更通用

func _process(delta: float) -> void:
    if not _is_active: return
    
    _timer += delta
    if _timer >= emit_interval:
        _timer = 0.0
        _spawn_ghost()

# 监听逻辑：逻辑驱动表现的核心
func _on_tag_changed(tag: StringName, count: int) -> void:
    # 当 "state.movement.forced" 存在时 (count > 0)，开启残影
    if tag == &"state.movement.forced":
        _is_active = (count > 0)
        # 重置计时器，保证开始瞬间立即生成一个
        if _is_active: 
            _spawn_ghost()
            _timer = 0.0

func _spawn_ghost() -> void:
    if not target_mesh: return
    
    # 1. 创建网格实例副本
    var ghost = MeshInstance3D.new()
    ghost.mesh = target_mesh.mesh
    
    # 2. 复制变换信息 (Transform)
    # 必须使用全局变换，防止残影跟随主角移动
    add_child(ghost) # 先添加进树，才能设置全局坐标
    ghost.top_level = true # 关键：脱离父节点变换，留在原地
    ghost.global_transform = target_mesh.global_transform
    
    # 3. 设置材质
    # 必须 duplicate 材质，否则修改 alpha 会影响所有残影
    var mat = ghost_material.duplicate()
    ghost.material_override = mat
    
    # 4. 使用 Tween 驱动消散 (Fade Out)
    var tween = create_tween()
    
    # 这里的 "shader_parameter/alpha_factor" 对应 Shader 里的 uniform
    tween.tween_property(mat, "shader_parameter/alpha_factor", 0.0, duration) \
        .set_trans(Tween.TRANS_SINE).set_ease(Tween.EASE_IN)
        
    # 5. 销毁
    tween.tween_callback(ghost.queue_free)
```

### 四、 整合效果预览

现在，当你按下冲锋键时，会发生一连串精妙的反应：

1.  **输入层**：检测按键 -\> 调用 Ability `Charge`。
2.  **Ability**：应用 `GE_PhysicsMotion`。
3.  **Effect (逻辑)**：
      * 开始 Tween 物理位移。
      * **添加 Tag `state.movement.forced`**。
4.  **GhostTrailGenerator (表现)**：
      * 监听到 Tag 增加。
      * `_is_active = true`。
      * 开始在身后每隔 0.05秒 留下一个青色的、慢慢消失的残影。
5.  **Effect 结束**：
      * Tween 完成。
      * **移除 Tag `state.movement.forced`**。
6.  **GhostTrailGenerator**：
      * 监听到 Tag 归零。
      * `_is_active = false` -\> 停止生成。
7.  **结果**：角色停下，身后的残影还在慢慢消失，**视觉残留感极佳**。

---

在没有 Tag 的情况下，**“信号（Signal）”** 是最标准、最解耦的替代方案。这也是 Godot 的核心哲学。

我们可以利用 `GameplayAbilityComponent` 作为**中转站**。

### 替代方案：基于事件的通信 (Event-Driven)

**核心思路：**

1.  **逻辑层 (`GE_PhysicsMotion`)**：不修改 Tag，而是通过组件发出一个**通用业务信号** `gameplay_event`。
2.  **表现层 (`GhostTrailGenerator`)**：监听组件的这个信号，根据事件 ID (`charge_start` / `charge_end`) 来开关特效。

这样既不需要 Tag 系统，又保持了“逻辑不直接引用表现”的解耦原则。

-----

### 第一步：给组件加个“大喇叭”

修改 `GameplayAbilityComponent.gd`，增加一个通用信号。这比专门为冲锋写一个 `charge_started` 信号要好，因为以后“格挡”、“暴击”都能用它。

```gdscript
# gameplay_ability_component.gd

# 通用游戏事件信号
# event_id: 事件名 (例如 "charge_start")
# args: 附加参数
signal gameplay_event(event_id: StringName, args: Dictionary)

# 提供一个辅助函数方便外部调用
func trigger_event(event_id: StringName, args: Dictionary = {}) -> void:
    emit_signal("gameplay_event", event_id, args)
```

-----

### 第二步：修改冲锋效果 (`GE_PhysicsMotion`)

将原代码中 `add_tag` 的部分替换为 `trigger_event`。

```gdscript
# GE_PhysicsMotion.gd (只修改 apply 部分)

func _apply(target, instigator, context) -> void:
    # ... (前面的物理/Tween初始化代码保持不变) ...

    # 5. [修改点] 替代 Tag，发送开始信号
    var ability_comp = _find_ability_component(body)
    if ability_comp:
        # 通知所有人：冲锋开始了！
        ability_comp.trigger_event(&"charge_start")
    
    # 6. 启动 Tween
    tween.tween_method(...)
    
    # 7. [修改点] Tween 结束回调
    tween.finished.connect(func():
        if ability_comp:
            # 通知所有人：冲锋结束了！
            ability_comp.trigger_event(&"charge_end")
    )
```

### 第三步：修改残影生成器 (`GhostTrailGenerator`)

让它监听这个通用信号，而不是监听 Tag。

```gdscript
# GhostTrailGenerator.gd
extends Node3D

# ... 变量定义不变 ...

func _ready() -> void:
    var owner_node = get_parent()
    # 获取组件逻辑保持不变...
    
    if _ability_comp:
        # [修改点] 监听 gameplay_event
        if _ability_comp.has_signal("gameplay_event"):
            _ability_comp.gameplay_event.connect(_on_gameplay_event)

# [修改点] 信号回调逻辑
func _on_gameplay_event(event_id: StringName, args: Dictionary) -> void:
    match event_id:
        &"charge_start":
            _start_ghosts()
        &"charge_end":
            _stop_ghosts()

func _start_ghosts():
    _is_active = true
    _spawn_ghost()
    _timer = 0.0

func _stop_ghosts():
    _is_active = false
```

### 💡 这个方案的教学意义

这正是你在 **开发日志** 里可以重点讲解的“架构演进”：

1.  **阶段一 (Day 4)：** 我们只需要简单的交互，所以用 **Signal**。简单、直接、高效。
2.  **阶段二 (Day 26)：** 当状态变得非常复杂（例如：处于“冲锋”时不仅要有残影，还要免疫控制、增加撞击伤害、改变受击音效...），单纯发 Signal 就不够用了，我们需要一个**持久化的状态管理**。这时候我们引入 **Tag 系统**。

**结论：**
目前用 **Signal 方案** 是最完美的。它让你能顺利推进课程，实现了完全相同的视觉效果，同时为未来的架构升级留下了伏笔。

---

现在的架构中，技能默认为“发射即不管（Fire-and-Forget）”，这对于火球术、普攻没问题。但对于冲锋，**技能的生命周期 = 动作的持续周期**。如果冲锋还没冲完就允许施放下一个技能（被打断），那逻辑就全乱了。

我们不需要打破原则，只需要引入一个标准的 GAS 概念：**“技能结束策略 (End Policy)”**。

我们将技能分为两类：

1.  **立即结束型 (Instant/Fire-and-Forget):** 普攻、火球。效果打出去，逻辑层就结束，进入后摇（可打断）。
2.  **手动结束型 (Manual/Await):** 冲锋、引导法术。技能必须等待某个“信号”才能结束，在此期间**绝对锁定**。

以下是实现这一机制的最优雅方案：

-----

### 第一步：改造 AbilityComponent (支持手动结束)

我们需要修改 `GameplayAbilityComponent.gd`，把之前简单的“效果应用即解锁”逻辑升级一下。

```gdscript
# gameplay_ability_component.gd

# 当前正在执行的技能 ID (互斥锁)
var current_executing_ability: StringName = &""

# 提交施法 (上锁)
func commit_cast(ability_id: StringName) -> bool:
    if not super.commit_cast(ability_id): return false
    
    # 【上锁】标记当前正在执行
    current_executing_ability = ability_id
    return true
```

### 第二步：改造 ActiveAbility (增加配置项)

在 `ActiveAbility.gd` 中增加一个枚举，让策划决定这个技能的生命周期。

```gdscript
# active_ability.gd
class_name ActiveAbility

enum EndPolicy {
    INSTANT,  # 瞬发：效果应用后立即结束逻辑 (进入后摇可打断状态)
    MANUAL    # 手动：需要显式调用 end_ability 才能结束 (全程霸体/不可打断)
}

@export_group("Execution Rules")
## 技能结束策略
## 普攻选 INSTANT，冲锋/旋风斩选 MANUAL
@export var end_policy: EndPolicy = EndPolicy.INSTANT
```

### 第三步：实战——设计“冲锋”技能逻辑

现在，我们如何让冲锋技能在“冲完”那一刻调用 `end_ability` 呢？
答案就是利用我们上一节做好的 **`gameplay_event`** 信号！

我们不需要在 Ability 基类里写复杂的逻辑，只需要利用 `await` 或者 `Signal` 连接。

**在 `ChargeAbility.gd` (继承自 ActiveAbility) 中重写 `_on_cast`：**

```gdscript
# abilities/charge_ability.gd
extends ActiveAbility

func _init():
    # 冲锋必须手动结束，锁死输入
    end_policy = EndPolicy.MANUAL 

func _on_cast(ability_comp: Node, target: Node, context: Dictionary = {}) -> void:
    # 1. 监听通用事件 (等待 GE_PhysicsMotion 发回来的完成信号)
    # 注意：连接一次性信号，防止重复调用
    if not ability_comp.gameplay_event.is_connected(_on_gameplay_event):
        ability_comp.gameplay_event.connect(_on_gameplay_event.bind(ability_comp))
    
    # 2. 应用冲锋效果 (这里会启动 Tween 并发送 charge_start)
    super._on_cast(ability_comp, target, context)

# 事件回调
func _on_gameplay_event(event_id: StringName, args: Dictionary, ability_comp: Node):
    # 当收到“冲锋结束”信号时
    if event_id == &"charge_end":
        # 3. 【核心】显式告诉组件：技能逻辑结束了，解锁！
        ability_comp.end_ability(ability_id)
        
        # 断开连接，清理垃圾
        if ability_comp.gameplay_event.is_connected(_on_gameplay_event):
            ability_comp.gameplay_event.disconnect(_on_gameplay_event)
```

### 流程图解 (Sequence)

1.  **玩家按键** -\> `commit_cast` -\> **上锁** (`current = "Charge"`)。
2.  **施法** -\> `ChargeAbility` 应用 `GE_PhysicsMotion`。
3.  **Tween 运行中** -\> 0.3秒内，玩家狂按攻击键。
      * `can_cast` 检查 `current` 是 "Charge"。
      * 因为 Charge 还没结束，`current` 没清空。
      * **施法失败！** (实现了“释放过程不可打断”)。
4.  **Tween 结束** -\> 发送信号 `charge_end`。
5.  **ChargeAbility** -\> 收到信号 -\> 调用 `ability_comp.end_ability("Charge")`。
6.  **组件** -\> **解锁** (`current = ""`)。
7.  **下一帧** -\> 玩家可以移动或攻击了。

### 为什么这个设计“优雅”？

1.  **符合直觉**：`EndPolicy` 的配置非常容易理解。
2.  **通用性强**：
      * **普攻：** `INSTANT`。伤害打出，锁解开，后续交给动画后摇（可通过移动打断）。
      * **冲锋：** `MANUAL`。冲锋结束信号触发解锁。
      * **旋风斩（引导）：** `MANUAL`。玩家松开按键 -\> 脚本逻辑停止 -\> 调用 `end_ability` -\> 解锁。
3.  **闭环完整**：它利用了你现有的 `gameplay_event` 系统，没有任何硬编码的 `await get_tree().create_timer()`。

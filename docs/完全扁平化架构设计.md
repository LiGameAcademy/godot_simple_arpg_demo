# 完全扁平化架构设计

## 核心观点

### 当前架构问题

1. **PassiveAbility 本质上是特性**：它的核心功能（学习时应用状态、遗忘时移除状态）完全可以作为特性实现
2. **ActiveAbility 和 GameplayAbility 可以整合**：`ActiveAbility` 只是添加了主动技能特有的逻辑，这些逻辑可以整合到基类中
3. **继承层次冗余**：`GameplayAbility -> ActiveAbility` 和 `GameplayAbility -> PassiveAbility` 的继承关系可以用特性系统替代

### 目标架构

```
GameplayAbility (统一基类)
└── features: [
    ActiveFeature,        // 主动技能特性（提供施放流程）
    PassiveFeature,       // 被动技能特性（学习时应用状态）
    CooldownFeature,      // 冷却特性（可选）
    CostFeature,          // 消耗特性（可选）
    ComboFeature,         // 连击特性（可选）
    ProjectileFeature,    // 投射物特性（可选）
    ...
]
```

## 设计提案

### 方案：完全扁平化架构

#### 核心设计

```gdscript
# 统一的基础技能类（包含所有功能）
class_name GameplayAbility extends Resource
    @export var ability_id: StringName
    @export var ability_name: String
    @export var features: Array[AbilityFeature] = []
    
    # 主动技能相关属性（可选，向后兼容）
    @export var cooldown_duration: float = 0.0
    @export var costs: Array[AbilityCostBase] = []
    @export var cast_point_time: float = 0.0
    @export var execution_duration: float = 0.0
    @export var targeting_strategy: TargetingStrategy = null
    
    # 被动技能相关属性（可选，向后兼容）
    @export var statuses: Array[GameplayStatusData] = []
    
    # 统一的生命周期方法
    func can_cast(...) -> bool
    func commit_cast(...) -> bool
    func cast(...) -> void
    func update(delta: float) -> void
    func handle_learned(...) -> void
    func handle_forgotten(...) -> void

# 主动技能特性
class_name ActiveFeature extends AbilityFeature
    # 提供主动技能的施放流程钩子
    func can_cast(...) -> bool
    func commit_cast(...) -> bool
    func on_cast(...) -> void
    func on_cancel(...) -> void
    func on_completed(...) -> void

# 被动技能特性
class_name PassiveFeature extends AbilityFeature
    # 提供被动技能的生命周期钩子
    func on_learned(...) -> void
    func on_forgotten(...) -> void
    # 学习时应用状态，遗忘时移除状态
```

#### 使用示例

```gdscript
# 主动技能 = ActiveFeature + CooldownFeature + CostFeature
var active_ability = GameplayAbility.new()
active_ability.ability_id = &"fireball"
active_ability.features = [
    ActiveFeature.new(),
    CooldownFeature.new(),
    CostFeature.new(),
    ProjectileFeature.new()
]

# 被动技能 = PassiveFeature
var passive_ability = GameplayAbility.new()
passive_ability.ability_id = &"strength_buff"
passive_ability.features = [
    PassiveFeature.new()
]

# 混合技能 = ActiveFeature + PassiveFeature（学习时获得被动效果，也可以主动施放）
var hybrid_ability = GameplayAbility.new()
hybrid_ability.ability_id = &"blessing"
hybrid_ability.features = [
    ActiveFeature.new(),
    PassiveFeature.new(),
    CooldownFeature.new()
]
```

## 实现细节

### 1. GameplayAbility 整合

**当前**：
- `GameplayAbility`：基础数据和方法
- `ActiveAbility`：主动技能逻辑（冷却、消耗、前摇等）
- `PassiveAbility`：被动技能逻辑（学习时应用状态）

**整合后**：
- `GameplayAbility`：包含所有功能，通过特性决定行为

**关键点**：
- 保留所有属性（向后兼容）
- 通过特性决定哪些功能启用
- 如果配置了 `ActiveFeature`，启用主动技能逻辑
- 如果配置了 `PassiveFeature`，启用被动技能逻辑

### 2. ActiveFeature 实现

```gdscript
class_name ActiveFeature extends AbilityFeature
    @export var cast_point_time: float = 0.5
    @export var execution_duration: float = 0.0
    @export var targeting_strategy: TargetingStrategy = null
    @export var animation_name: StringName = &"cast_spell_default"
    
    func can_cast(ability: GameplayAbility, context: AbilityContext) -> bool:
        # 检查标签、状态等
        return true
    
    func commit_cast(ability: GameplayAbility, context: AbilityContext) -> bool:
        # 启动前摇计时器
        return true
    
    func on_cast(ability: GameplayAbility, context: AbilityContext) -> void:
        # 应用状态或效果
        pass
```

### 3. PassiveFeature 实现

```gdscript
class_name PassiveFeature extends AbilityFeature
    @export var visible_in_ui: bool = true
    
    func on_learned(ability: GameplayAbility, ability_comp: Node, status_comp: Node) -> void:
        # 应用状态（从 ability.statuses）
        var instigator = ability_comp.get_parent()
        if is_instance_valid(instigator) and not ability.statuses.is_empty():
            var context = AbilityContext.create()
            context.instigator = instigator
            context.input_target = instigator
            ability._apply_statuses_to_targets(instigator, instigator, context, null)
    
    func on_forgotten(ability: GameplayAbility, ability_comp: Node, status_comp: Node) -> void:
        # 移除状态
        var entity = ability_comp.get_parent()
        if is_instance_valid(entity) and is_instance_valid(status_comp):
            ability._remove_all_statuses_from_entity(entity, status_comp)
```

### 4. 向后兼容

**策略**：
- 保留 `ActiveAbility` 和 `PassiveAbility` 类（标记为 deprecated）
- 它们内部使用特性系统实现
- 用户可以选择使用新方式或旧方式

```gdscript
## @deprecated: 请使用 GameplayAbility + ActiveFeature 的组合方式
class_name ActiveAbility extends GameplayAbility
    func _init():
        # 自动添加 ActiveFeature
        if features.is_empty():
            features.append(ActiveFeature.new())
```

## 优点

1. **完全扁平化**：所有技能都是 `GameplayAbility`，无继承层次
2. **极致灵活**：可以任意组合特性，如"主动+被动"混合技能
3. **数据驱动**：完全通过配置实现，无需创建新类
4. **一致性**：所有技能使用相同的基类和特性系统
5. **易于扩展**：添加新行为只需创建新特性

---

## 缺点

1. **类型安全降低**：编译时无法保证技能类型正确
2. **配置复杂**：需要配置多个特性才能实现基本功能
3. **学习曲线**：需要理解特性系统才能使用
4. **迁移成本**：需要重写现有技能配置
5. **可能过度设计**：对于简单技能，特性系统可能过于复杂

---

## 迁移策略

### 阶段 1：创建特性系统（已完成）
- ✅ `AbilityFeature` 基类
- ✅ `ComboFeature`、`ProjectileFeature`、`ChannelingFeature`、`MagicFieldFeature`

### 阶段 2：创建 ActiveFeature 和 PassiveFeature
- 创建 `ActiveFeature`（整合 `ActiveAbility` 的核心逻辑）
- 创建 `PassiveFeature`（整合 `PassiveAbility` 的核心逻辑）

### 阶段 3：整合 GameplayAbility
- 将 `ActiveAbility` 的功能整合到 `GameplayAbility`
- 通过特性决定行为

### 阶段 4：标记旧类为 deprecated
- 保留 `ActiveAbility` 和 `PassiveAbility`（向后兼容）
- 它们内部使用特性系统实现

### 阶段 5：迁移现有技能（可选）
- 逐步将现有技能迁移到新方式
- 提供迁移工具或文档

## 推荐方案

### 短期（当前阶段）

**保持混合模式**，但创建 `ActiveFeature` 和 `PassiveFeature`：
1. 创建 `ActiveFeature` 和 `PassiveFeature`
2. 保留 `ActiveAbility` 和 `PassiveAbility`（向后兼容）
3. 它们内部可以使用特性系统

### 中期（6-12个月）

**评估完全扁平化**：
1. 创建原型：整合 `GameplayAbility` 和 `ActiveAbility`
2. 对比测试：评估灵活性和复杂度
3. 用户反馈：收集使用反馈

### 长期（1-2年）

**根据反馈决定**：
- 如果完全扁平化确实更灵活且用户接受度高，则完全迁移
- 如果混合模式已经足够，则保持现状

---

## 结论

**完全扁平化架构是可行的**，但需要：
1. **谨慎评估**：确保灵活性提升值得复杂度增加
2. **渐进迁移**：分阶段实施，保持向后兼容
3. **用户反馈**：收集实际使用反馈，决定是否完全迁移

**当前建议**：
- 先创建 `ActiveFeature` 和 `PassiveFeature`
- 保留 `ActiveAbility` 和 `PassiveAbility`（向后兼容）
- 评估完全扁平化的实际效果
- 根据反馈决定是否完全迁移
